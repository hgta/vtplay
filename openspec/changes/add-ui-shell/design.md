## Context

当前 `Main.qml` 的结构极简：`header`（36px，内含 logo 方块 + "打开"按钮）+ 视频区（`VideoSurface` + 错误提示 + `ControlsBar`）+ 快捷键 + 两个定时器。没有菜单、侧栏、信息条、状态栏。

已知的既有问题：

- **看不到播的是什么**：`win.title` 恒为 `"VTPlay"`；顶栏无文件名；`ControlsBar` 只有时间码。`MediaInfo` 也没有文件名字段。
- **进度靠轮询**：`Main.qml` 里
  ```qml
  Timer { interval: 100; running: true; repeat: true
          onTriggered: { player.positionChanged(); player.durationChanged(); player.statusChanged() } }
  ```
  在 QML 侧**手动 emit C++ 信号**来强制刷新——反模式，既耗 CPU 又不平滑。
- **状态不持久化**：窗口尺寸由屏幕尺寸计算得出，位置/音量/最近播放每次重置。
- **无播放列表/最近打开**：切换视频必须重开文件对话框。

此前修复过的 QML 交互问题（控制条 z 序遮挡点击、`opacity`/`visible` 绑定循环、seek 阻塞主线程）说明：**布局改动必须回归验证交互**，不能只看视觉。

## Goals / Non-Goals

**Goals:**

- 功能可见且可达：菜单与快捷键一致，常用操作不超过两次点击
- 当前媒体信息在**任何状态下**都可见（含全屏）
- 进度刷新事件驱动，移除 QML 轮询
- 窗口几何、音量、最近打开持久化
- 侧栏承载播放列表与最近打开

**Non-Goals:**

- 主题/皮肤切换
- 多窗口、画中画
- 播放列表拖拽排序（先支持点击切换、增删、循环模式）
- 文件关联与安装程序（属分发范畴）

## Decisions

### D1：采用「顶部精简栏 + 可收起侧栏」而非传统菜单栏

```
┌──────────────────────────────────────────────────────────────┐
│ [V] VTPlay  IMG_2327.MP4 ☰ 菜单        —  □  ✕              │ ← 顶栏（精简）
├───────────┬──────────────────────────────────────────────────┤
│ 菜单分组   │                  视频画面                        │
│ ─────────  │                                                  │
│ 播放列表   │   ┌────────────────────────────────────────┐     │
│ ▸ 2317.MP4 │   │ ▶ 00:12/01:30 ━━●━━ 🔊 ⚙ ⛶ ⬇  IMG_2327 │     │
│   2319.MP4 │   └────────────────────────────────────────┘     │
│ ─────────  │                                                  │
│ 最近打开   │                                                  │
└───────────┴──────────────────────────────────────────────────┘
```

- 播放器的主视觉是画面，菜单栏会永久占用一行；侧栏可一键收起
- 侧栏天然承载播放列表 / 最近打开，未来也能放字幕轨、AI 字幕结果
- 备选（顶部菜单栏）改造量更小、更传统——保留为可切换布局（见 Open Questions）

### D2：进度刷新改为事件驱动

- **移除** QML 中每 100ms 手动触发 `positionChanged()` 的 `Timer`
- 在 `PlayerController` 内部用一个 `QTimer`（约 30ms）读取音频时钟并 `emit positionChanged()`
  - `positionSec()` 只是一次原子读，代价极低
  - 节流集中在一处，便于统一调整（进度条本身另有 80ms 动画，30ms 刷新足够平滑）
  - 窗口不可见/最小化时可降频或暂停（省电）
- QML 侧只保留属性绑定：`text: Theme.fmtTime(player.position)`

### D3：当前媒体信息三处显示

| 位置 | 内容 | 说明 |
|---|---|---|
| 窗口标题 | `VTPlay — IMG_2327.MP4` | 任务栏悬停、Alt+Tab 也能看到 |
| 顶栏信息条 | `IMG_2327.MP4 · 2160×3840 · 60fps · 54Mbps · 157MB` | 常驻，信息密度高 |
| 控制条内联 | 文件名 | **全屏时唯一可见处** |

数据来自 `add-video-export` 的 `media-metadata` 能力（`MediaInfo` 扩展 + 格式化辅助）。本变更只消费，不重复解析。

### D4：状态持久化用 `QSettings`

- 保存：窗口几何（**正常态**几何，非全屏）、音量、静音、最近打开（≤10 条）、始终置顶、上次导出目录
- 时机：启动读取；退出（`aboutToQuit`）写入；最近打开在打开时即写（防崩溃丢失）
- **不持久化全屏状态**（避免启动即全屏的意外）
- 启动校验：若保存的几何不在任何屏幕可用区域内（拔插显示器），回退为默认居中

### D5：播放列表模型

- 会话内队列（`QStringList` + 当前索引），用 `QAbstractListModel` 或简单 `QStringList` + 信号（按实现成本选）
- 拖入多个文件 → 追加到队列并播放第一个
- 循环模式：不循环 / 单曲 / 列表（影响 `Eof` 时的行为）
- 与"最近打开"的区别：播放列表是**本次会话的队列**，最近打开是**历史记录**（只读、可清空）

### D6：截图实现

- MVP 使用 `QQuickWindow::grabWindow()` 截取视频区并裁剪黑边
  - 优点：拿到的是"用户实际看到的画面"，实现简单
  - 缺点：分辨率受显示尺寸限制（高 DPI 下为物理像素，等于当前显示分辨率）
- 保存至系统图片目录：`<basename>_<yyyyMMdd_HHmmss>.png`
- 完成后 Toast 提示，提供"打开所在文件夹"
- **原分辨率截图**（从解码帧取全尺寸）列入后续：需要 core 支持"另取一帧不缩放的路径"

### D7：菜单与快捷键单一来源

- 所有菜单项显示其快捷键；快捷键集中在 `Main.qml` 顶部的 `Shortcut` 列表维护，菜单文本引用同一份定义（避免两处漂移）
- 新增：`Ctrl+E` 导出、`Ctrl+S` 截图、`Ctrl+T` 始终置顶、`Ctrl+L` 侧栏、`?` 快捷键一览

## Risks / Trade-offs

- **[侧栏与悬浮控制条的鼠标显隐逻辑冲突]** → 侧栏展开时控制条常驻显示，不参与自动隐藏
- **[窗口几何持久化后越界（多显示器拔插）]** → 启动时校验是否落在任一屏幕 `availableGeometry` 内，否则回退默认居中
- **[改动触及此前修过的交互问题]** → 回归清单：控制条按钮可点、进度条可拖、双击全屏、拖放打开、暂停时静音、seek 后不停播
- **[播放列表与最近打开概念重叠，用户困惑]** → UI 上分组标题区分，最近打开置于列表下方且标注"历史"
- **[截图分辨率受显示尺寸限制]** → UI 上不承诺原始分辨率；后续增强
- **[事件驱动刷新在暂停时也要更新]** → 暂停/seek 时单次 emit，不能只靠周期定时器

## Migration Plan

1. 依赖 `add-video-export` 的 `media-metadata` 先落地（否则文件名无数据来源）
2. 先做「三处文件名显示 + 事件驱动刷新」——这是用户最直接的需求，且改动面小
3. 再做外壳（顶栏 / 侧栏 / 菜单结构）
4. 最后做播放列表、截图、状态持久化
5. 每步都按回归清单验证交互

**回滚**：外壳改动集中在 `Main.qml` 与新增 QML 文件，可独立回退；C++ 侧新增属性均为附加项。
