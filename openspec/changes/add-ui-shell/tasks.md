## 6g. 真正的逐帧步进（前进 + 后退）

上一轮我误记为「前进可行、后退核心层不支持」——实际核心层是个 MVP 桩，**前进也没生效**：

```cpp
void MediaPipeline::stepFrame() {
    if (status_.load() != PlayerStatus::Paused) return;
    // MVP 简化：仅刷新最近一帧后立即显示（实际需要按帧间隔解码一帧）。
    VideoFrame v = frames_.peekLatestVideo();
    if (v.valid) frames_.pushVideo(std::move(v));   // 把最近一帧原样推回，画面不动
}
```

- [x] 6g.1 `MediaPipeline::stepFrame(int direction)`：以**当前显示帧的 PTS**（`lastVideoPts_`，
      在 `takeVideoUpTo()` 里记录）为基准做加减，而不是用时钟——时钟可能停在两帧之间的
      任意位置，用它加减一帧会时而跳两帧、时而原地不动
- [x] 6g.2 两个方向都走 seek：前进 `base + 1.2×帧间隔`、后退 `base − 0.5×帧间隔`。
      前进**没有**采用「只推时钟」的零成本写法——见下方陷阱 15
- [x] 6g.3 `VideoRenderer::onTick` 的取帧容差改为「播放中 20ms、暂停/逐帧 0」。
      原实现恒定 20ms，比一帧（60fps 下 16.7ms）还大，步进会顺手把下一帧吃掉
- [x] 6g.4 `PlayerController::stepFrame(direction)`：播放中调用先暂停（逐帧是「检视」动作），
      并立即补发位置与状态，连续步进时进度不滞后
- [x] 6g.5 快捷键改成精度递进：`←/→` 5 秒、`Shift+←/→` 1 秒、`Ctrl+←/→` 单帧；菜单同步

      每步精确 ±0.0167s（60fps 一帧），前进 5 步再后退 5 步精确回到起点 4.483s**

## 8. 过程中踩到的坑（均已修正，备后人查阅）

1. **`flags` 写成绑定会导致无法全屏**：QML 每次重新求值都会 `setFlags`，而
   `setFlags` 会把全屏状态打回普通窗口——表现为「按 F 没反应」。改为只在
   「切换置顶」与「退出全屏」两个时刻命令式应用。
2. **`header` 用 `ColumnLayout` 收不起来**：布局引擎会写 Layout 自身的
   `implicitHeight`，覆盖 QML 里的绑定。外层包一个普通 `Item` 控制高度即可。
3. **`visible: width > 1` 与宽度动画互相打断**：动画刚离开 0 就触发不可见、动画被中断、
   属性回退到绑定值，宽度在 4.4 → 0 → 51.5 之间反复振荡。改为始终可见 + `clip`。
4. **窗口比屏幕可用区还大**：原初始尺寸 `Math.max(720, ...)` 在 150% 缩放的小屏上
   得到 1280×720，而可用区只有 1280×672，底部控制条整条落到任务栏之下、根本点不到。
   改为 `Math.min(期望值, 可用区)`。
5. **`Popup` 的 `parent` 只能是 Item**：`parent: menu`（另一个 Popup）会报
   "Unable to assign ... to QQuickItem"。两者同在窗口内容项下，直接换算坐标即可。
6. **跨文件 id 不可见**：`Sidebar.qml` 里不能引用 `Main.qml` 的 `toast`，
   一律通过信号回传由 Main 处理。
7. **关闭窗口后进程不退出**：关闭把 `visible` 置 false，紧随其后的 `flags` 变化又会
   把窗口显示回来。加 `shuttingDown` 守卫后 `closing → aboutToQuit → exec returned 0` 正常。
8. **日志等级映射不能用数组下标**：`QtInfoMsg` 枚举值为 4、排在 `QtFatalMsg(3)` 之后，
   按下标取会把 `qInfo` 标成 FATAL、`qWarning` 标成 INFO。已改为 `switch` 映射。
9. **`header` 的高度不能从子项反推**：写成 `topBar.implicitHeight + infoBar.height` 会触发
   `Binding loop detected for property "implicitHeight"`（子布局会写回自身 implicitHeight）。
   改用 `Theme` 常量 + `player.hasMedia` 推导。
10. **窗口几何必须按「外框」校验**：QML `Window.x/y` 是**客户区**坐标，标题栏与边框在它之上/之左。
    只按客户区判断会把标题栏整条推到屏幕之上（实测 `y=0` 时外框在 `-45`，窗口无法拖动）。
    控制器因此持有 `QWindow*`，用 `frameMargins()` 把客户区换算成外框再校验、回填时再换回来。
11. **前向声明 `QWindow` 必须写在命名空间之外**：在 `namespace vtapp` 内写
    `class QWindow* window_` 会声明出 `vtapp::QWindow` 这个全新类型，编译期报
    `incomplete type` 且 `qobject_cast` 永远失败。
12. **嵌套 Popup 的坐标是相对外层 Popup 的**：子菜单写 `x: menu.x + menu.width` 会把外层位置
    重复计入，子菜单整体下移约 `menu.y`（约 2.5 行）。正确写法是 `x: menu.width + 2`。
    当时是为了绕开 `parent: menu` 的报错才误改成绝对坐标。
13. **不要用缩略图判断颜色**：屏幕截图被缩放后，深色菜单被我误读成「白底」，为此白跑了几轮。
    改为**放大裁剪 + 像素直方图**采样（见 `px.ps1` / `crop.ps1`）后一次就看清了：
    子菜单实测 `#1A1A1A` 65.5% + `#242424` 27.9%，本就正确。
15. **帧队列「超容量丢最旧」让「推时钟式前进」不可靠**：`FrameQueue` 的视频侧是丢帧而非阻塞
    （音频侧才阻塞生产者），而解码线程在暂停时并不停。所以「只把时钟推一格」看似零成本，
    实际下一帧随时可能已被丢掉——自测里连续前进两步后就取不到帧了。逐帧前进必须走 seek
    重解，代价是几十~几百毫秒，但结果确定。
16. **自测脚本必须与渲染层同口径**：修了 `VideoRenderer` 的取帧容差却忘了改自测里的模拟取帧，
    于是前进稳定走成 2 帧、后退被容差拉回原帧，差点又去改核心逻辑。测试里的「模拟渲染层」
    一旦和真实渲染层不一致，测出来的幅度就不是用户看到的东西。
17. **测试断言不能「一看到变化就返回」**：后退要回关键帧重解，seek 后先解出来的是关键帧本身
    （可能比目标早半秒），那一刻读到的是中间态。必须等画面**稳定**（连续多拍不变）再取值。
14. **测试脚本的两个环境坑**（非应用问题，但会误导结论）：
    - 日志超过 1MB 会轮转，按「行号偏移」取新日志会整体落空 → 应按时间或取末尾若干行；
    - 会话没有前台窗口时（`GetForegroundWindow()` 返回 0、`CopyFromScreen` 报
      *The handle is invalid*）按键与截屏都会失效 → 用 `AttachThreadInput` 强制取得前台可改善；
      `PostMessage` 投递按键虽然有效，但 QML `Shortcut` 仍需要窗口处于激活态。
